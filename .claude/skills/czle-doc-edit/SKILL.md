# GolfFix 문서 편집

## 목적

CLAUDE 워크플로우 문서의 `{중괄호}` 지시를 제자리에서 적용한다. Markdown 계획, PR 설명, 릴리즈 노트, 리뷰 요약, 리포트 초안에 사용한다.

## 범위

- 대상: Markdown, 텍스트, PR 본문 초안, 릴리즈 노트, HTML 리포트 초안
- Kotlin/XML/Gradle/JSON 소스 코드는 이 스킬로 수정하지 않는다.
- 코드 변경이 필요하면 일반 구현/계획 흐름으로 전환한다.
- `.claude/plans/`와 `.claude/reports/` 문서는 수정 가능하다.

## 구문

수정할 문장, 단락, 리스트 항목, 섹션 옆에 지시를 배치한다:

```markdown
이번 변경은 분석 리포트 다운로드 안정성을 개선합니다.
{더 구체적으로: 어떤 사용자 시나리오가 좋아지는지 적기}

- QA: 통합 리포트 다운로드 확인
{실패/빈 상태도 포함}
```

일반적인 지시:

- `{구체화}`: 추상적 표현을 코드/시나리오/근거로 구체화한다.
- `{줄이기}`: 반복되거나 장황한 문장을 줄인다.
- `{톤}`: PR/릴리즈 노트 톤에 맞게 문체를 조정한다.
- `{근거 추가}`: 파일, 함수, diff, 시나리오 근거를 추가한다.
- `{삭제}`: 문장이나 단락을 제거한다.

## 워크플로우

1. 목표, 범위, 제외 대상을 한국어로 짧게 정리한다.
2. 대상 파일을 읽고 모든 `{...}` 지시를 찾는다.
3. 각 지시는 가장 가까운 문장/단락/리스트/섹션에만 적용한다.
4. 여러 파일을 편집할 때 용어, 티켓 번호, 위험도, QA 항목의 충돌을 확인한다.
5. 지시를 반영한 뒤 `{...}` 마커를 제거한다.
6. 수정 요약에 처리한 지시 수, 주요 변경, 남은 확인 사항을 기록한다.

## 보호막

CLAUDE.md의 글쓰기 원칙을 따른다. 이 스킬에만 해당하는 항목은 아래와 같다.

- 근거가 없는 기술 사실은 `확인 필요`로 남긴다.
- PR/릴리즈 노트는 재현 가능한 사용자 영향, 코드 근거, QA 경로를 우선한다.
- HTML 리포트는 장식보다 첫 화면 요약, 위험도, QA 경로의 스캔 가능성을 우선한다.

## 출력 형식

```markdown
처리 결과

- 대상 파일: ...
- 처리한 지시: N개
- 주요 변경: ...
- 남은 확인 사항: ...
```

남은 확인 사항이 없으면 `없음`으로 적는다.
